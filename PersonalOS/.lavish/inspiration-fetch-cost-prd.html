03 · Experience

抓取前講上限，抓取後留證據。

提交前

本次最多約 US$0.002 · 1 request · Instagram post info。

估價不等於付款授權；未核價時直接講「可能收費」。

完成後

1 request · ≈ US$0.002

保存 endpoint、價格核對時間、provider request ID 及狀態；不保存 key。
01

Dashboard 只讀 Supabase，載入或 refresh 絕不呼叫 TikHub。

02

Timeout、無 HTTP status、source job unknown：費用一律 unknown。

03

ToAPI credits 與 TikHub 美元費用分開，不混成同一指標。

06 · Acceptance

九個情境，先算完成。

現有資料4 個無估價 runs → `— · 0/4`，不可顯示零。
單一成功1 × US$0.002 → `≈ US$0.002 · 1/1`。
混合資料只加總已知，顯示「部分估算 · 2/3」。
明確免收費有 provider 規則與回應才可顯示 verified zero。
狀態不明Timeout／unknown 不當零，不自動重試。
匯入兼容新 Runs 可讀；舊資料不猜價、不覆寫。
RLS每個 owner 只看到自己的 runs。
無隱藏費用進入／刷新 Dashboard 不打 TikHub。
Reload重新載入後數字與狀態一致。
07 · Risks & rollout

唔改 schema，分三步推出。

RISKS

價格與折扣會變

保存 endpoint、單價、核對日期及依據；維持「估價，非帳單」文案。

共用 key 難以歸因

不宣稱 workspace 實際帳單；以安全上限或 provider quote 為準。

ROLLOUT
1

純計算＋UI 狀態與回歸測試。

2

修正 Runs 匯入及 live adapter 保存。

3

獲明確付費授權後做一次 live 驗收。
